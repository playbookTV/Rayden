# Rayden UI — verification sweep, 21 September 2026

## Verdict

**Rayden is materially improved, but the sweep is not clean.** The calm, approachable direction fits broad product teams. The current homepage uses a useful interactive workspace example and clear entry points. No new broad visual redesign is warranted. The remaining concerns are readable content, truthful states, reliable navigation, and examples that consumers can safely copy.

Of the previous **47 findings, 17 are fixed, 9 are partially fixed, and 21 remain open**. This sweep adds **2 findings**, leaving **32 actionable items: 6 P1, 25 P2, and 1 P3**. No P0 was confirmed. Partial repairs are counted once, not as new defects. IDs below retain the previous report’s numbering; 48–49 are additions.

The immediate priorities are the clipped collapsed-sidebar submenu, remaining contrast failures, missing scatter-chart alternatives, inaccurate form-control examples, unnamed starter switches, and misleading table selection.

## Verified closures

- **#1 — The documented blocks import cannot resolve:** Built-package ESM consumer resolves @raydenui/ui/blocks and imports LoginBlock successfully.
- **#2 — Optional chart dependencies are required by the root import:** The isolated consumer imports the root with no chart.js or react-chartjs-2 installed. Charts now use ./chart.
- **#3 — An initially open modal crashes server rendering:** renderToString of an initially open Modal returns an empty string without throwing; mounting is deferred to the browser.
- **#4 — Documentation search is broken in the production preview:** Production build indexes 49 pages. Live search for Accordion returns component and subsection results.
- **#6 — Starter templates contain reproducible UI contract errors:** The targeted compiler check across 12 TypeScript starter variants now finds zero of the previously tracked UI contract errors (previously 16 in 10 files). Full independent installs of all starters were not performed.
- **#7 — Collapsed accordion content still receives keyboard focus:** Collapsed content is inert. The new normal interaction test verifies skipping it with Tab, opening it, and returning focus on close.
- **#9 — The password reveal control is hidden from assistive technology:** Login uses the accessible trailingAction slot; the hidden-focus flag is gone and the reveal-control interaction test passes.
- **#10 — TableBlock row actions and selection controls are unnamed:** Named row selectors/actions and a meaningful actions-column header remove the previous TableBlock naming flags.
- **#11 — Progress indicators do not expose their visible labels:** Visible labels now name progress bars/circles; normal interaction tests verify their names and values.
- **#15 — SearchableTableBlock claims to sort without sorting:** Local sorting now reorders data; normal interaction test verifies Alice/Zelda ascending and descending, rather than only the indicator.
- **#16 — ButtonGroupItem unexpectedly submits surrounding forms:** Grouped buttons default to type=button. The normal test verifies that only an explicit submit button submits.
- **#17 — Interactive tooltip rerenders steal focus while typing:** Focus is moved on the opening transition, not every callback/child identity change. The hello typing regression passes without losing focus.
- **#18 — Form adapters lose nested-field errors:** Adapters use getFieldState for nested names. The nested profile.email error interaction regression passes.
- **#19 — The select adapter returns errors that Select cannot display:** The adapter returns the error message, and Select now accepts it, displays helper text, and sets aria-invalid/describedby. Source and clean type check verify the integration.
- **#20 — Banner clipping hides notification content on phones:** The fixed-height clipping is removed. Narrow-layout regression passes, and the live 390px Banner page shows descriptions within its 308px preview content width. Rayden’s sm breakpoint is 320px; hidden sm:inline does not hide descriptions at the tested phone width.
- **#21 — The search-table toolbar exceeds phone width:** Wrapping toolbar controls and responsive input widths pass the existing narrow-layout interaction regression.
- **#24 — Title-table Search and Sort buttons do nothing:** Title-toolbar Search and Sort now require explicit onSearchClick/onSortClick callbacks and are hidden when absent.

## Standards and systemic causes

Contrast measurements concern WCAG 1.4.3 (4.5:1 for ordinary text). Missing chart alternatives concern 1.1.1; control names and inaccurate states concern 4.1.2; missing state relationships also affect 1.3.1. Keyboard focus visibility is assessed against 2.4.7. Small-target recommendations distinguish the 24px AA criterion and its exceptions from a preferable 44px touch area. Reduced motion is a user-preference/usability concern; this report does not label every animation an AA violation.

The main repeated cause is incomplete contract coverage: a clean static example can coexist with broken callback types, clipped open states or inaccurate selection. The new tests are useful, but need representative data and assertions about content as well as basic rendering. Shared color tokens also need paired foreground/surface validation, rather than isolated substitutions.
